
CDN (Content Delivery Network) — это распределённый кэш контента, расположенный в разных регионах мира для быстрой доставки данных пользователям.

---
В прошлом  CDN использовались для доставки контента и статических файлов вроде фото, видео, html, css, js файлов

**CDN (Content Delivery Network)** представляет собой распределённую сеть серверов, размещённых в различных регионах мира. Основная задача CDN — доставлять контент пользователям с ближайшего географически узла сети.

Например, если пользователь из Китая запрашивает изображение, то эффективнее отдать его с CDN-узла, расположенного в Китае или соседнем регионе, чем передавать данные напрямую с сервера, находящегося, например, в Европе или США.

Благодаря этому:

- уменьшается задержка (latency);
- сокращается количество промежуточных сетевых переходов (hops);
- снижается нагрузка на магистральные каналы связи;
- уменьшается нагрузка на origin-сервер (основной сервер приложения);
- ускоряется загрузка контента для конечного пользователя;
- повышается отказоустойчивость системы.

CDN обычно хранит кэшированные копии часто запрашиваемого контента (изображений, видео, CSS, JavaScript, документов и даже ответов некоторых API) и отдаёт их напрямую пользователям без обращения к origin-серверу


Современные CDN умеют гораздо больше

---
### 1. Статические файлы (классический сценарий)

```
User -> CDN -> image.jpg
```

Кэшируются:

- PNG
- JPG
- WebP
- CSS
- JS
- PDF
- видео

Это самый простой и распространённый вариант.

---
### 2. Кэширование API

Например:

```http
GET /api/products
```

Товары меняются раз в час.

CDN может сохранить ответ:

```json
[
	{"id": 1, "name": "iPhone"},
	{"id": 2, "name": "Samsung"}
]
```

Следующие запросы будут обслуживаться без обращения к backend.

```
User -> CDN
```

вместо

```
User -> CDN -> Backend
```

---
### 3. Защита от DDoS

Многие CDN выступают как прокси перед backend.

```
User -> CDN -> Backend
```

Если прилетит миллион запросов:

```
1 000 000 запросов -> CDN
```

CDN может:
- фильтровать ботов;
- ограничивать скорость запросов (rate limit);
- блокировать подозрительный трафик.

До backend дойдёт только нормальный трафик

---
### 4. WAF (Web Application Firewall)

Например кто-то отправляет:

```sql
?id=1 OR 1=1
```

или

```html
<script>alert(1)</script>
```

CDN может заблокировать запрос ещё до backend.

---
### 5. Edge Functions

Самая интересная современная возможность.

Код запускается прямо на узлах CDN.

```
User -> CDN (код выполняется тут) -> Backend
```

Например:

```python
if country == "KZ":
	return kazakh_version

if country == "US":
	return english_version
```

Backend может вообще не вызываться.

Такие возможности есть у:

- [Cloudflare Workers](https://workers.cloudflare.com?utm_source=chatgpt.com)
- [AWS CloudFront Functions](https://aws.amazon.com/cloudfront/features/?utm_source=chatgpt.com)

---
### 6. Балансировка трафика

CDN может направлять пользователей на разные датацентры.

```
Казахстан -> Сервер Алматы
Европа    -> Сервер Франкфурт
США       -> Сервер Нью-Йорк
```

Пользователь автоматически попадёт на ближайший backend.

---
### Как это выглядит для senior backend инженера

Современный CDN — это уже не просто "хранилище картинок".

Он может выполнять роль:

```
CDN
├── Кэш статических файлов
├── Кэш API
├── Reverse Proxy
├── DDoS Protection
├── WAF
├── Rate Limiter
├── Гео-маршрутизация
├── Edge Compute
└── Балансировка нагрузки
```

Поэтому в современной архитектуре часто говорят не просто "CDN", а **Edge Network** — сеть узлов на границе интернета между пользователем и твоим backend.

Если провести аналогию с тем, что ты уже изучал:

```
Redis       -> кэш перед PostgreSQL
Nginx       -> прокси перед Backend
CDN         -> глобальный прокси и кэш перед всей системой
```

То есть CDN сегодня — это не только про статические файлы, а про целый набор инфраструктурных сервисов на пути между пользователем и твоим приложением.
